# 实验室生信数据归档 SOP｜试用稿 v0.4

本流程用于将值得长期保留的生信数据从计算临时目录（scratch）、个人分析目录或外部交付目录移交到实验室长期存储（archive），并在数据目录库中登记。文件保存在长期盘，SQLite 记录数据是什么、从哪来、哪一版、在哪里可读。

研究者按需在终端 TUI 发起整理，AI 起草清单，研究者补充科学信息并确认取舍，获授权的人员按清单执行。执行工具可自行选择。

## 接收哪些数据

| 来源 | 从哪里取得登记依据 |
| --- | --- |
| HelixWeave 流程产物 | 从已完成写入的产物清单选文件，保留 run ID、准确产物修订、相关样本、参数、参考版本及必要 QC。 |
| 自行完成的其他生信分析 | 包括独立流程、R/Python 分析、单细胞或 Hi-C 结果。记录实际分析者或流程、脚本或软件版本、输入数据版本和必要参数。可直接从已有目录归档，无须先导入 HelixWeave 跑一次。 |
| 测序平台、合作者或公共库交付的数据 | 按实际来源记录提供方、交付批次或 accession、版本和随附清单。实验室负责保管且有权复制的，按下述流程接收；由对方保管的，登记稳定引用、托管方和已知版本，状态标为“仅引用”。 |

## 怎样分类

| 日常查找入口 | 登记依据与粒度 |
| --- | --- |
| 课题 | 选择归属项目的稳定 ID 和可读名称；结果不因课题改名而搬盘。无法确认归属，先待核对。 |
| 细胞或材料 | 用样本的确切修订关联细胞类型、细胞系等已知属性。三者分别填写，不从文件名猜。组织材料、混合样本或尚未注释的数据，可以注明组织、混合、未知或不适用，不强填细胞类型。 |
| 实验 | 记录实验方法和具体实验记录/批次的已知身份；方法相同的两次实验仍可区分。下游计算记录分析方法及父数据，不虚构一次湿实验。 |
| 科学结果 | 一份可独立解释和引用的结果为一个逻辑单位。记录结果类型、版本、必要成员和来源。样本级、整批级、跨组比较分别记录作用范围，不能把整批结果算成某一个细胞样本的结果。 |

长期盘按项目和结果版本各保存一份受管内容；按细胞、实验或其他条件生成目录视图或索引。一份跨组比较可以从两个组找到，但仍是同一份结果。临时盘仍按 run 分开。原始数据与已受管参考应有独立保管位置，不能把工作区当唯一原件。

## 从临时目录迁入 archive

| 步骤 | 操作与完成条件 |
| --- | --- |
| 1. 选定保留内容 | AI 根据获准使用的产物清单或交付说明列出主文件、读取所需的索引、解释所需的 QC、注释及来源。研究者逐项确认“保留、仅引用、暂存、不纳入、待核对”，决定是否保留昂贵的中间结果。失败结果如需留存，标明实际 QC 状态。 |
| 2. 确认清单 | 确定目标项目、数据或结果 ID、版本、每个成员的角色和目标相对路径。对要复制的成员，在源文件写入结束后记录字节数和 SHA-256，有交付方校验值时一并核对。缺少必需成员或归属待核对时，保留源文件，单列受影响的结果。 |
| 3. 复制到长期盘暂存区 | 执行人按确认清单复制，保留源文件。暂存区与最终目录位于同一长期存储卷，便于核验后整份交付。只登记引用的条目跳过传输。文件已在批准的长期位置时，可原地核验并登记。 |
| 4. 在目标端核验 | 对照确认清单逐项检查目标文件可读、字节数和 SHA-256 一致、必要成员齐全。源文件在复制期间发生变化、校验失败或目标同名版本内容不符，停止交付该版本；查明原因后从同一清单重试，或重新确认变更的清单。 |
| 5. 发布并登记 | 把核验通过的数据连同清单发布到项目的固定版本目录，保留历史版本。通过现有登记入口记录可读位置、来源、版本及执行回执，再按项目和版本从目录库查回，打开返回位置的主文件。成功后标为“已归档”。若文件已就位而登记尚未完成，标为“已复制、待登记”，保留源文件；重试时先核对已有副本和记录，避免重复复制或登记。 |
| 6. 按保留策略清理 scratch | 已归档后，另行确认保留期已满、归档副本仍可读、恢复运行或下游分析已不依赖旧路径，再由有清理权限的人处理临时副本。唯一原件和他方托管原件不在清理范围内。 |

目录示例为 `storage/projects/<项目ID>/results/<结果ID>/<版本>/`。原始输入可放在同项目的 `inputs/`。只迁移位置且内容校验一致，沿用同一数据版本，补登记核验过的位置。修改文件内容则保留旧版，另记新版。

## 一份清单，跟到归档结束

- **归属与来源**　项目 ID 和名称、数据或结果 ID 与版本、样本及实验关系、来源类型、run 或外部交付标识、父数据版本。未知项注明依据缺口。
- **逐个文件**　在受管清单中记录源位置、作用范围（样本／整批／跨组）、角色、取舍和理由、目标相对路径、源字节数与摘要、目标核验结果。仅引用项记录外部定位符和版本。
- **执行回执**　清单版本、确认人、执行人和时间、最终位置、目录库登记标识、回读结果、尚待处理的问题。公开视图隐藏真实物理路径。

## 两个示例

**HelixWeave 的 Hi-TrAC 结果。** 从一次运行中选择项目需要的 all/noBg 配对产物及整批 summary。配对产物关联具体样本，summary 按整批保留一次，排序缓存留在 scratch。核验后从目录库按项目和版本查回结果，确认长期盘上的主文件可读，再进入工作副本保留期管理。

**独立 R 分析的两组比较。** 从分析者的工作目录直接接收差异表、生成脚本及必要参数。一份结果同时关联 A、B 两组的确切输入版本。若 B 只写了 latest，先标为待核对；若 B 由合作者长期托管，可用对方确认的固定版本作为父数据引用。比较结果本身照常复制、核验并登记，两个组均可查到同一份结果。
