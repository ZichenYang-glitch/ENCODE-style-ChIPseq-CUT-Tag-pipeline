## Product and scientific boundary

HelixWeave v0.3.0 is a local workstation or small trusted-team product. Its
default registry contains the ENCODE-style ChIP-seq/CUT&Tag/ATAC/MNase workflow
and `bulk-rnaseq`. Bulk input authoring and validation remain available without
runtime assets; execution is available only after an operator supplies and
admits the complete fixed runtime binding.

The release does not include Bulk RNA-seq OCI images, JDK, Nextflow,
references, STAR/Salmon indexes, rRNA databases, FASTQ data, runtime caches, or
credentials. Tiny synthetic gates prove execution and result contracts, not
biological validity or production-scale performance.

Authentication, multi-user isolation, HPC/cloud executors, object storage,
Tower/Wave, a third adapter, cross-attempt resume, and production support SLAs
remain outside v0.3.0.

A live audit of the unchanged exact lock on 2026-07-25 reported 28
package-level findings: one critical, 23 high, and four moderate. Three paths
reach production dependencies; 25 are limited to build, test, or generation
tooling. The maintained exploit conditions and fixed-version floors are in

Independent review found no v0.3.0 release blocker inside the documented
loopback or trusted-team boundary. No `npm audit fix`, force fix, lock rewrite,
or unrelated major upgrade was applied.

The lazy new-analysis chunk remains approximately 1.20 MB minified (385 KB
gzip), is not loaded by workflow list/detail routes, and is dominated by the
schema form, editor, and validation libraries. It remains a bounded performance
follow-up rather than a correctness or release blocker.

## Final qualification contract

The exact release-metadata candidate must pass:

- PEP 517 wheel and sdist builds plus a deterministic single-prefix
  qualification source-trial archive;
- independent fresh wheel and sdist installs outside the source tree with
  `pip check`;
- distribution/import ownership, primary and compatibility console/module
  entry points, package data, OpenAPI, both workflow IDs, fresh database, and
  revision 07→08 migration checks;
- source-trial frontend install, tests, typecheck, production build, browser
  path, and real primary-CLI doctor;
- repeat OpenAPI/Orval generation with zero drift;
- deterministic Python, Ruff, formatting, documentation links, and
  `git diff --check`;
- recomputation of the 83-file protected execution closure;
- two independent read-only reviews; and
- exact-HEAD CI, Lint, Lock Check, merged-main checks, then exact tag-push CI.

The `v*` tag trigger runs the existing deterministic CI on the tag's peeled
commit. It does not enable the protected Bulk runner.

## Publication boundary

At this candidate commit, `v0.3.0` and the GitHub Release do not yet exist.
After the metadata PR is reviewed, merged, and green on exact main, the
authorized procedure may create one immutable annotated tag, wait for its
exact CI, build final assets from that tag, and create one non-draft,
non-prerelease GitHub Release.

No PyPI, npm, conda, Docker, OCI, or other registry upload is authorized. The
repository, import namespace, compatibility CLIs, workflow identities, remote
PR branches, GitHub Environment policies, reviewer rules, fork approvals, and
protected evidence artifact remain unchanged.
