# HelixWeave 的 TDP 流程

**项目试行 · Trace → Distill → Prune**

TDP 贯穿现有的开发、复审与收尾。沿用已知契约的普通小修，在原 PR 记录复现、修正和验收即可。发现反例、改变方案、识别出可复用的约束，或碰到会误导下一位同事的旧说明时，启动相应步骤。工单和 PR 沿用现有模板。

### Trace · 记录演进过程

实施者在原工单或 PR 留下改变判断的那次尝试。写明当时的版本、输入或配置，看到了什么，为什么转向，还缺什么证据。链接能复现现象的测试、运行或提交。观察和原因假设分别写，交接只摘录必要且可分享的证据。

### Distill · 提炼有效认知

实施者提出一句能指导下次行动的结论，复审者用反例检查其适用范围并给出验收意见。合入由项目授权的合入人决定。若一次最小复现能从源码或锁定依赖解释原因，就足以为这个条件写回归。遇到偶发问题先保留观察。要改变科学默认，另由科学负责人依据相应的数据和方法裁决。

优先把可以自动判定的行为固化在对应代码和回归测试里。用户或运维人员需要执行的步骤写进专题指南；长期设计取舍写进 spec 或架构决策记录。只有跨任务通用的做法进入开发 SOP。Agent skill 引用现行条款，各处共用一份正文。

遇到矛盾先核对时间和前提。行为随版本演进，就标出替代版本；两个结果适用于不同输入，就分别写清条件。若同一版本、同一条件下证据仍冲突，在原工单并列证据，标为待裁决，指定补验负责人，保留仍可确定的部分。

### Prune · 清理过时指引

实施者把同一主题中已经失效的命令、重复叮嘱和旧示例随替代它们的 PR 一起更新，复审者从旧入口验证能找到新做法。主持人负责跨 PR 的 README、路线图及 agent 入口。仍服务旧版本的约定注明范围；有历史价值的快照移入已有档案，并从现行入口链接。已被取代且无独立信息的文字可在可回退的文档 PR 中删除。

Prune 针对开发指引。科研文件的迁移、核验与清理按[实验室生信数据归档 SOP](../../.agents/skills/helixweave-archive-plan/references/lab-archive-sop.md)执行。失败记录、绑定提交的验收结果及其出处沿用各自的保留规则。新版本、新输入或新证据推翻现有结论时，从该条款链接新的 Trace，重新核定范围。

### 两个仓库实例

- **Bulk 作业的 Redis 预检。** 一次受保护运行在初始化 worker 时发现 Redis 地址格式有误。维护者把检查提前到科学计算之前，沿用 worker 的配置解析器并实际执行 PING。通过预检的证据覆盖这个运行环境的配置与连通性。整套 Bulk 流程的验收引用对应提交的执行结果。维护操作示例时，从同一处回归核对有效和失效的格式。[已合入的预检](https://github.com/ZichenYang-glitch/ENCODE-style-ChIPseq-CUT-Tag-pipeline/pull/261) · [配置与连通性回归](../../test/bulk_rnaseq_real_execution/test_gate_redis_precheck.py)
- **WashU 的第 501 个产物。** 500 份普通报告排在一条有效轨道前面，暴露了只读第一页会漏轨道的问题。由此固定的行为是成员仍能找到并选择这条轨道。HTTP 回归覆盖第 501 项和跨页代次变化，专题契约记录用户可见结果；路线图把读者引到已合入的实现，并标明早期草案的去向。以后更换分页实现，可沿同一验收用例复核。[验收用例与证据分工](https://github.com/ZichenYang-glitch/ENCODE-style-ChIPseq-CUT-Tag-pipeline/blob/52973b6020e1bd6c9b44e08fdf1ae8b526a43666/docs/development/washu-browser-read-contract.md#L131) · [路线图中的现行入口](https://github.com/ZichenYang-glitch/ENCODE-style-ChIPseq-CUT-Tag-pipeline/blob/52973b6020e1bd6c9b44e08fdf1ae8b526a43666/docs/development/workflow-platform-agent-roadmap.md#L9)

### 怎么判断试行有效

挑一次确实改变做法的交付，让未参与的 agent 从原工单开始，找到证据和现行入口，说明结论适用于什么，以及哪一步仍未验证。这三件事都能做到，交接就够了；找不到时，直接修对应的链接或条款。
